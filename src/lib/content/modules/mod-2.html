def mse(y_real, y_pred):
    """Error cuadrático medio. Ambas listas deben tener igual longitud."""
    if len(y_real) != len(y_pred):
        raise ValueError("Las listas deben tener la misma longitud")
    errores = [(real - pred) ** 2 for real, pred in zip(y_real, y_pred)]
    return sum(errores) / len(errores)

print(mse([3, -0.5, 2, 7], [2.5, 0.0, 2, 8]))   # 0.375

Programación orientada a objetos

En ML, las clases sirven para encapsular estado y comportamiento: un modelo con sus pesos, un dataset con sus transformaciones, un pipeline con sus pasos. Scikit-learn usa esta interfaz: fit, predict, score.

Pythonpoo.py
class StandardScaler:
    """Estandarización: (x - media) / desviación estándar."""

    def __init__(self):
        self.media_ = None
        self.sd_ = None

    def fit(self, X):
        n = len(X)
        self.media_ = sum(X) / n
        varianza = sum((x - self.media_) ** 2 for x in X) / n
        self.sd_ = varianza ** 0.5
        return self

    def transform(self, X):
        if self.media_ is None:
            raise RuntimeError("Llama a fit() antes de transform()")
        return [(x - self.media_) / self.sd_ for x in X]

    def fit_transform(self, X):
        return self.fit(X).transform(X)

scaler = StandardScaler()
datos = [10, 12, 14, 16, 18]
print(scaler.fit_transform(datos))
print("media aprendida:", scaler.media_)   # 14.0

El guion bajo final en media_ es una convención de Scikit-learn para atributos aprendidos durante fit. Distinguirlos de los hiperparámetros evita fugas de información.

Principio de responsabilidad única Una función debe hacer una cosa. Una clase debe tener una razón para cambiar. En un pipeline, separa carga de datos, preprocesamiento, entrenamiento y evaluación. Facilita probar y reemplazar piezas.

Ejemplo integrador: clase de regresión lineal simple

Pythonregresion_oo.py
class RegresionLinealSimple:
    def __init__(self, lr=0.01, epochs=1000):
        self.lr = lr
        self.epochs = epochs
        self.w = 0.0
        self.b = 0.0
        self.historial = []

    def fit(self, X, y):
        n = len(X)
        for _ in range(self.epochs):
            y_pred = [self.w * x + self.b for x in X]
            error = [yp - yr for yp, yr in zip(y_pred, y)]
            dw = 2 / n * sum(e * x for e, x in zip(error, X))
            db = 2 / n * sum(error)
            self.w -= self.lr * dw
            self.b -= self.lr * db
            mse = sum(e ** 2 for e in error) / n
            self.historial.append(mse)
        return self

    def predict(self, X):
        return [self.w * x + self.b for x in X]

X = [1, 2, 3, 4]
y = [2, 4, 5, 4]
modelo = RegresionLinealSimple(lr=0.01, epochs=2000).fit(X, y)
print(f"y = {modelo.w:.3f}x + {modelo.b:.3f}")
print("predicciones:", [round(p, 2) for p in modelo.predict(X)])

Por qué la vectorización importa

1 Bucle vs. vector

Calcular el cuadrado de un millón de números con un bucle de Python tarda del orden de 50–100 ms; con NumPy, del orden de 1–3 ms. La diferencia no es solo velocidad: el código es más corto y menos propenso a errores.

En entrenamiento de modelos, esto se multiplica por miles de iteraciones y millones de parámetros. La vectorización es una necesidad, no un lujo.

Aplicación: regresión lineal con NumPy

Pythonregresion_numpy.py
import numpy as np

# Datos: x = [1,2,3,4], y = [2,4,5,4]
X = np.array([1., 2., 3., 4.])
y = np.array([2., 4., 5., 4.])

# Añadimos columna de unos para el intercepto
Xb = np.column_stack([np.ones_like(X), X])
w = np.linalg.solve(Xb.T @ Xb, Xb.T @ y)
print("b0, b1 =", w)                 # [2.0 0.7]

y_pred = Xb @ w
residuos = y - y_pred
sse = (residuos ** 2).sum()
sst = ((y - y.mean()) ** 2).sum()
r2 = 1 - sse / sst
print("R² =", r2)                    # 0.5158

# Descenso del gradiente vectorizado
w_gd = np.zeros(2)
lr = 0.05
for _ in range(2000):
    grad = 2 / len(X) * Xb.T @ (Xb @ w_gd - y)
    w_gd -= lr * grad
print("gradiente:", w_gd)            # ≈ [2.0 0.7]

def resumen_eda(df):
    print("Forma:", df.shape)
    print("\nTipos:\n", df.dtypes.value_counts())
    faltantes = df.isna().mean().sort_values(ascending=False)
    print("\n% faltantes:\n", (faltantes * 100).round(1).head())
    print("\nDuplicados:", df.duplicated().sum())
    numericas = df.select_dtypes("number")
    print("\nResumen numérico:\n", numericas.describe().T)
    if len(numericas.columns) > 1:
        print("\nCorrelaciones:\n", numericas.corr().round(2))

Curvas de aprendizaje

Pythoncurvas.py
epocas = np.arange(1, 51)
train_loss = 0.9 * np.exp(-epocas / 12) + 0.08
val_loss = 0.9 * np.exp(-epocas / 12) + 0.08 + 0.12 * (epocas / 50) ** 2

plt.figure(figsize=(7, 4))
plt.plot(epocas, train_loss, label="entrenamiento", color="#3355c8")
plt.plot(epocas, val_loss, label="validación", color="#b42318")
plt.axvline(epocas[np.argmin(val_loss)], color="gray", linestyle=":", label="mejor época")
plt.xlabel("época"); plt.ylabel("pérdida"); plt.legend(); plt.grid(alpha=.3)
plt.title("Diagnóstico de overfitting")
plt.show()

Si la pérdida de entrenamiento sigue bajando mientras la de validación sube, el modelo está memorizando. Si ambas son altas, hay underfitting. Estas dos curvas son el diagnóstico más rápido y útil de un entrenamiento.

Buenas prácticas de visualización Etiqueta siempre los ejes y las unidades; usa escalas logarítmicas cuando los valores abarcan varios órdenes de magnitud; no cortes el eje Y para exagerar diferencias; incluye intervalos de confianza cuando compares grupos; y no uses gráficos 3D si un 2D comunica mejor.

Jupyter, Colab y buenas prácticas

16 minFlujo de trabajoReproducibilidad

Un notebook es un laboratorio; un script es una fábrica. Saber cuándo usar cada uno y cómo mantener ambos reproducibles es una habilidad profesional.

Anatomía de un notebook

  • Celdas de código: se ejecutan individualmente; el estado vive en el kernel.
  • Celdas Markdown: documentación, ecuaciones LaTeX, imágenes y conclusiones.
  • Kernel: proceso que mantiene variables en memoria. Reiniciar y ejecutar todo es la prueba de reproducibilidad.
  • Outputs: pueden quedar obsoletos si ejecutas celdas fuera de orden. No confíes en un notebook con celdas saltadas.

La semilla no garantiza reproducibilidad total Fijar la semilla ayuda, pero el orden de operaciones en GPU, las versiones de las librerías y el hardware pueden cambiar los resultados. Registra siempre versiones y configuración. Un resultado sin contexto no es ciencia.

Del notebook al script

  1. Explora en el notebook: gráficos, hipótesis, pruebas rápidas.
  2. Cuando una celda funciona, muévela a una función en src/.
  3. Escribe pruebas para las transformaciones críticas.
  4. Orquesta el pipeline con un script o un Makefile.
  5. Versiona datos y modelos con DVC o Git LFS si son grandes.
  6. Documenta cómo reproducir: python train.py --config config.yaml.

Checklist de un proyecto limpio

  • Semilla fijada y documentada.
  • Entorno reproducible (requirements.txt o environment.yml).
  • Datos crudos intactos; transformaciones en código.
  • Train/validación/test separados antes de cualquier preprocesamiento que aprenda parámetros.
  • Métricas reportadas con media y dispersión entre folds.
  • Ningún dato del test usado para elegir hiperparámetros.
  • Conclusiones separadas de los resultados.
  • Limitaciones y sesgos conocidos documentados.
